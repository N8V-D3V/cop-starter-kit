# Build Phase

Version: 0.1.0

---

## Purpose

Replace stubs with real implementation while preserving the behavior proven in the Shape phase.

---

## Accountable Owner

The Build phase must have a designated Accountable Owner before work begins.

The Build Accountable Owner is responsible for ensuring implementation work is understood, delegated, executed, reviewed, and completed according to the contract, protocols, architecture plan, and stubbed behavior.

The Accountable Owner does not have to write all code personally. Accountability for completing the phase remains with the Accountable Owner.

---

## Responsibilities

- Implement modules according to approved protocols
- Replace stub behavior with real behavior
- Implement orchestration without embedding module logic
- Preserve contract-defined behavior
- Preserve the behavior demonstrated by stubs
- Add or update tests required for implementation confidence
- Keep implementation inside approved boundaries

---

## Inputs

- Approved contract document
- Protocol definitions
- Architecture plan
- Stub modules and stub orchestration
- Stub demo evidence or notes

---

## Outputs

- Real module implementations
- Real orchestration logic
- Tests, if applicable
- Implementation notes

---

## Exit Criteria

- Real modules conform to protocols
- Real orchestration coordinates through protocols
- Implementation does not introduce behavior outside the contract
- Real behavior matches the stubbed flow
- Defined tests pass or unresolved test gaps are documented

---

## Completion Celebration

The Build phase is complete when the team can say:

> It is real now.
