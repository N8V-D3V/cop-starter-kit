# Define Phase

Version: 0.1.0

---

## Purpose

Define what the system must do before deciding how it will be built.

---

## Accountable Owner

The Define phase must have a designated Accountable Owner before work begins.

The Define Accountable Owner is responsible for ensuring the contract is clear, complete, testable, and ready for downstream work.

The Accountable Owner may delegate research, drafting, review, or refinement work. Accountability for completing the phase remains with the Accountable Owner.

---

## Responsibilities

- Translate feature ideas into contract-defined behavior
- Define actors, inputs, outputs, and data models
- Define success behavior, failure modes, and edge cases
- Define constraints, observability, and acceptance criteria
- Surface unknowns as open questions

---

## Inputs

- Feature description
- User or business requirements
- Existing system context, if available

---

## Outputs

- Contract document using `docs/cop/contract-template.md`
- Open questions, if behavior is unclear

---

## Exit Criteria

- Contract behavior is complete, consistent, and unambiguous enough to shape
- Inputs and outputs are explicit
- Failure modes and edge cases are defined
- Acceptance criteria are testable
- Undefined behavior is documented as open questions

---

## Completion Celebration

The Define phase is complete when the team can say:

> We know what this must do.
